# Audit: what STATUS claims as built and is not

August 2026. Every finding below was checked against the code, then handed to
a second reader told to refute it. These are the ones that survived; several
were reproduced by running the engine. Line numbers are from the commit that
found them and will drift.

STATUS's "Not built" table turned out to be accurate — nothing listed as a gap
was secretly done. The problem is the other direction, which is the same
failure this file's predecessor recorded: **things listed as built that are
absent or materially thinner than claimed.** A known gap is manageable. A
false claim is not, because nobody goes looking.

Ordered by what a user loses. Struck-through rows are fixed; the rest are
not, and each is a live defect with a plan of its own in
[plans/gaps/](plans/gaps/README.md).

## Files this engine writes that are broken

| What | Where | Consequence |
| --- | --- | --- |
| ~~**Encryption + object streams writes a permanently unreadable file**~~ **FIXED** | `write.rs:675` numbers `/Encrypt` as `max+3`; `write_xref_stream` sizes the table at `max+3` and iterates `0..size`, so that object gets no entry | Reopening reports `is_encrypted=false`, `authenticate()` returns `NotEncrypted`, zero pages — while the content genuinely is ciphertext. Unrecoverable. No test sets both options |
| ~~**Every encrypted file has a wrong trailer `/Size`**~~ **FIXED** | `write.rs:706` writes `max+1` after `:675` emitted `/Encrypt` at `max+3` | Violates 7.5.5 Table 15. Passes only because this engine's own reader walks subsection headers rather than trusting `/Size` |
| ~~**Incremental updates understate `/Size`**~~ **FIXED** | `write.rs:563` takes it from the *changed* set, clobbering the correct value the caller passes at `edit.rs:1139` | A conforming reader must ignore every object above it — including the edited page's own `/Contents`. The object-stream path documents and fixes exactly this bug at `write.rs:781` |
| ~~**`compress` is silently ignored when `linearize` is on**~~ **FIXED** | `maybe_compress` has one caller, `write_entry`; the linearized writer uses `linearize::write_indirect`, which never sees `WriteOptions` | Measured 6,680 bytes against 27,424 for the same document |
| ~~**Every incremental update chained to the wrong offset**~~ **FIXED** | `edit.rs` passes `CosDocument::last_startxref` to `write::incremental_update`, and it returned `Revision::byte_range.end` — the byte past the last `%%EOF`, never the offset of a cross-reference section | 7.5.5 Table 15 makes `/Prev` the previous section's offset, so every update this engine wrote published a chain no reader could follow and **every object the update did not itself carry became unreachable**: a filled form reopened with its widgets, its appearance streams and its `/DR` font all null. Nothing caught it because the reader recovers, and only sometimes — a file whose catalog was *not* in the update falls to ladder level 3, rescans, finds everything, and reads correctly, which is the case every page-operation test happens to exercise; a file whose catalog *was* in the update stays at level 1 and quietly reads the rest as null. The regression test therefore asserts the **ladder level**, not the content, because the content is right either way in the case already covered. Found while building PRE-E's fixtures |
| **No encrypted file carries an `/ID`** | Nothing writes `Name::ID` into a trailer on any path; `build_encryption` consumes all 48 entropy bytes for the file key, the two salts and the `/Perms` filler, so there is none left and no design decision has been made about deriving one | 7.5.5 Table 15 requires `/ID` whenever `/Encrypt` is present. `qpdf --check` reports `invalid /ID in trailer dictionary` on every encrypted file this engine writes, linearized or not, and then two more warnings when it tries to read the array. R6 does not mix `/ID` into key derivation, so nothing fails to decrypt and no test noticed. Found by gap 19 pointing qpdf at its own output; it is not gap 19's defect and predates it. **Still open after gap 20, and it now costs an assertion:** qpdf suppresses its `No syntax or stream encoding errors found` summary once anything has warned, so that line cannot be asserted on an encrypted file directly — `qpdf_oracle.rs` asserts it on a `--decrypt`ed copy instead, and allows the `/ID` warning through *by name* so nothing else can hide behind it |

## Forms, whose entire purpose is that the value and the drawing agree

| What | Where | Consequence |
| --- | --- | --- |
| ~~**A field on two pages could be half filled and report success**~~ **FIXED** | `edit.rs`'s widget loop: `let Some(rect) = fill::widget_rect(..) else { continue; }`, with `set_field_value` returning `true` at the end regardless | 12.5.2 Table 164 makes `/Rect` required for every annotation, so a widget without one is a damaged file — and a field that appears on two pages is ordinary. Reproduced before the fix on exactly that shape: the widget with a rectangle drew `(Ada) Tj`, the widget without kept drawing `(Bob) Tj`, `/V` said `Ada`, and the call returned `true`. A document that looks filled and is wrong, which is the failure gap 27's own recommendation names as the reason a half-implementation is worse than none — sitting one level below where that gap looks for it. Now: ruling 2 degrades, so the value is written and every drawable widget is drawn; ruling 10 applies, so `fill_field` returns typed `SkippedWidget`s naming the object; and `set_field_value`, which cannot say "partly", says no and changes nothing — PRE-E |
| ~~**Nothing could express "these fields apply together or not at all"**~~ **FIXED** | No begin, commit or rollback anywhere on `DocumentEditor`; `set_field_value` wrote objects, appearance streams and `/NeedAppearances` immediately | A refused second value left the first written: measured, `name` read back `Ada` and `short` read back nothing, from one call pair. Gap 27 option A cannot be built on that — a calculation that sets three fields and fails on the fourth produces a form whose totals disagree with its inputs. Now `transaction(\|tx\| ...)` snapshots all four of the editor's mutable fields and restores them on `Err`, and `set_field_values` is the all-or-nothing multi-field apply built on it — PRE-E |

## Rendering that is wrong rather than missing

| What | Where | Consequence |
| --- | --- | --- |
| ~~**Optional content (OCG/OCMD) does not exist**~~ **FIXED** | No hits anywhere in `crates/`; `BDC`/`EMC` fall into the catch-all; `/OC` on an XObject is never read | A layer marked `/OFF` paints at full strength with an empty warnings list. Reproduced before the fix, on a 40 pt page whose one group is `/OFF`: the rectangle inside the scope rendered `(255, 0, 0)` with `warnings = []`. It now renders white and reports `HiddenOptionalContent { layer: "Construction lines" }`, and the same file with the group `/ON` renders red. Suppression is at the *paint*, so the same page's text still extracts — plan [06](plans/gaps/06-optional-content.md) |
| ~~**Text clip modes fail open**~~ **FIXED** | `render/lib.rs:654` returns early when an outline does not resolve, before the clip accumulates; `end_text` applies no clip | A base-14 page using `7 Tr` inked the entire canvas. This is the default configuration — the engine ships no faces |
| ~~**Shading patterns work on fills only**~~ **FIXED** | `stroke_pattern` is recorded and read nowhere | A gradient-stroked rule draws solid black with no warning. A *tiling* pattern fill correctly warns; the same pattern stroked paints black silently, which falsifies the "reported with a warning" gap row — plan [07](plans/gaps/07-stroked-patterns.md). Reproduced before the fix: both cases measured `(0, 0, 0)` with `warnings = []`. The text path had it too, on both halves of a `2 Tr` glyph |
| ~~**`/Decode` is dropped on the DCT and CCITT paths**~~ **FIXED** | Both return before `/Decode` is parsed | A JPEG with `/Decode [1 0]` renders identically to one without |
| ~~**JPEG and CCITT are unreachable behind any other filter**~~ **FIXED** | Both call `stream_raw`, which is undecoded bytes | `[/FlateDecode /DCTDecode]` renders a placeholder; the CCITT half has no error path and renders silently wrong pixels. The correctly staged bytes already exist and are never called |
| ~~**Inline images bypass the filter chain**~~ **FIXED** | Predictors are passed as `None` despite `/DP` being parsed; DCT and CCITT are refused | A Flate-with-predictor inline image decodes to noise, no error. Fixed by making the COS chain builder public rather than by copying it, so Table 10's defaults stay in one place; the fax goes through gap 16's `ccitt_samples`. Two further defects had to go first or `/DP` still never arrived — the abbreviation rewrite matched only names followed by a space, so `/F/Fl` left the whole `/Filter` entry unread, and 8.9.7's white space before `EI` was being kept as data |
| ~~**Oversized pages are cropped, not scaled**~~ **FIXED** | The shrink factor is computed and never returned | A page beyond the pixel ceiling renders its top-left corner with no warning. Fires on real paper: ANSI E at 300 dpi loses three quarters of the sheet |

## Fonts

| What | Where | Consequence |
| --- | --- | --- |
| ~~**CFF uses the character code as the glyph index**~~ **FIXED** | `resources.rs:909` — no charset, no CFF encoding, no `FDSelect`/`FDArray` anywhere | Code 65 fetched GID 65 — at three sites, not the one this row found. Measured before the fix: a subset font, which is what a producer embeds, drew *nothing at all*, and only a font with more glyphs than the code drew the wrong letter. Now: charset, string INDEX, standard strings, built-in encoding, CID-keyed `ROS`/FDArray/FDSelect, and 9.6.6's fallback order with `.notdef` reported at the end of it |
| ~~**OpenType/CFF renders as blank space, no warning**~~ **FIXED** | `sfnt.rs:46` accepts `OTTO`, so it takes the TrueType branch and `glyf::outline` returns an empty outline, which the renderer reads as a legitimate space | Nothing anywhere looks up the `CFF ` table tag |
| ~~**Predefined CMaps are identity stubs**~~ **FIXED** | `cmap.rs:66` — only `Identity-H`/`-V` were real; fourteen registry prefixes got a blanket 2-byte codespace and code-is-CID | ~~`90ms-RKSJ-H` is mis-split *and* mis-mapped, so the widths are wrong too. `is_approximate` has no callers~~ — all 202 CMaps of Adobe's registry are vendored and compiled at build time into 1.19 MB of deflated tables, behind `cmap-predefined` (default on). The finding was right about both halves and understated the prefix list, which was wrong in *both* directions: `RKSJ` matched nothing, since no registry name begins with it, while `83pv-RKSJ-H`, `78-RKSJ-H`, `Hankaku`, `Roman`, `HKscs-B5-H` and the `UniHojo-*` family matched nothing and fell through to a one-byte-per-code split. Two further defects the row could not see: 9.7.6.2's codespace bounds are per *byte* and were compared as one integer interval, which is exactly what separates GB18030's two-byte and four-byte codes; and 9.7.6.3 gives an undefined code its length from its lead byte, where the code consumed one byte and re-read a trail byte as a lead. `is_approximate` now has a production caller and a stored form on `Font`, and a CMap outside the set is named in a typed warning — plan [03](plans/gaps/03-predefined-cmaps.md) closed |
| ~~**Composite fonts compute the CID for widths but not for outlines**~~ **FIXED**, including the vertical half — plan [05](plans/gaps/05-vertical-metrics.md) closed | `CMap::cid` had one caller, inside `width_of` | ~~Wrong glyphs at correct spacing. `/CIDToGIDMap` is never read~~ — the CID now decides the glyph as well as the advance, `/CIDToGIDMap` is read in both forms with an out-of-range CID drawing `.notdef` *and reporting*, and the finding understated the defect: the glyph lookup did not use the raw code but sent it through `/ToUnicode` to a character and the character through the font's own `cmap`, which 9.7.4.2 never consults for a composite font. ~~`/W2` and `/DW2` are still absent, so vertical CJK still advances by horizontal widths~~ — both are now read, in every form Table 117 defines, with `/DW2` defaulting to `[880 -1000]` and `v_x` derived as half the horizontal width where 9.7.4.3 says it is; the displacement reaches the pen through 9.4.4's `ty` and the position vector reaches the glyph's placement transform. The vertical half of the row was understated in the same way its horizontal half had been: the *advance* was the visible symptom, and the position vector — which decides where inside its em box a vertical glyph sits — was applied nowhere. Two further defects sat in the same branch and are named in the plan's `As built`: `TJ` adjustments moved a vertical pen sideways rather than down its column, and `Th` was multiplied into a vertical advance that 9.4.4 does not scale. Plans [02](plans/gaps/02-cid-to-gid.md) and [05](plans/gaps/05-vertical-metrics.md) both closed |

## Completeness words that do not hold

- **Phase 07 "complete"** — five plan-scope items absent, including ~~bilinear
  and area-averaged image sampling (nearest-neighbour only, and living in the
  wrong crate)~~ **FIXED** — plan [12](plans/gaps/12-image-sampling.md):
  `tinker-pdf-raster::image` takes bytes, dimensions and a transform, and
  implements all four rows of the plan's own policy matrix. The row was right
  and one word short: `/Interpolate` was not merely unimplemented, it was
  *parsed* — in the inline-image abbreviation table, rewritten to its long
  spelling, and then read by nothing, with no field on the decoded image to
  carry it and no branch at the sample site to use it. The measurements are in
  the plan's `As built`; the one worth repeating here is that the determinism
  fixture added for this had to be built twice, because a linear ramp and a
  checkerboard are both reproduced identically at any pyramid depth and the
  first draft could not see the defect it was written for — and ~~no
  quadratic curve verb~~ **FIXED** — plan
  [13](plans/gaps/13-quadratic-path-verb.md): `Verb::QuadTo` is first class,
  the flattener has a quadratic arm sharing the cubic's step count, and
  `show_glyph` no longer raises anything. The row understated it. The
  up-conversion also carried a live bug — a quadratic following a `Close` took
  its start point from its own endpoint, because the helper that looked one up
  returns nothing after a close — which drew a visibly different curve, and
  which no `glyf` outline can reach but any `GlyphSource` implementor can.
  Plan 07 is amended twice: its verb set now matches the code, its `f32` point
  type still does not, and its "adaptive recursive subdivision" describes a
  flattener the crate has never had.
- ~~**Phase 07 cost** — every paint is O(canvas), not O(shape). `Path::bounds`
  exists and is called nowhere outside its own unit test~~ **FIXED** — plan
  [14](plans/gaps/14-bounded-painting.md). The row named one of three layers.
  Bounding the mask alone would have left `Canvas::fill_mask_with` walking the
  page whatever the mask covered, `Mask::intersect` allocating a second
  page-sized mask, `fill_with_pattern` running its inverse transform and its
  shading function over every pixel, and `fill`'s row loop scanning every row
  and testing every edge at all sixteen sub-scanlines — `height x 16 x edges`,
  which is why a 500-edge signature cost the same on a 200 px page as on an
  8000 px one. All three landed: **600 glyphs on US Letter at 300 dpi went
  from 5997.7 ms to 18.8 ms**, and the same 500-edge path over a sixteen times
  taller page went from 8.3 times the cost to 0.99. The output is bit-identical
  by construction and the six fingerprints did not move — so the guard against
  regression is an assertion on mask pixels *asked for*, not on pixels painted.
- ~~**Phase 04 "complete"** — `/Trapped` and three other in-scope items
  absent~~ **FIXED** — plan
  [22](plans/gaps/22-pdf-version-and-trapped.md): the version is now the later
  of header and catalog rather than whichever the catalog says, compared as
  numbers; an unreadable header reports the 1.7 baseline with a
  `HeaderMissing` warning instead of nothing; `/Trapped` is read.
- ~~**Metadata** — the empty-string rule is inverted, so a field present and
  empty reads as absent~~ **FIXED** — plan
  [21](plans/gaps/21-metadata-absent-vs-empty.md).
- **`RenderOptions.cancel`** — documented as checked between scanline bands;
  it is not, so a single very large fill runs to completion — plan
  [15](plans/gaps/15-cancellation.md).

## What to do with this

Fix order is by what a user loses, which is the order above. The four writer
bugs and the redaction bug come first: they produce files that are broken or
that leak, and no amount of downstream work compensates.

The rendering and font findings are all the same shape — a capability that
exists, is reachable, and is wrong in a way that looks plausible. That is the
class this project has been fighting since the first audit, and the reason
every fix in it lands with a test that would have caught it.
