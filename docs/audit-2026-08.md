# Audit: what STATUS claims as built and is not

August 2026. Every finding below was checked against the code, then handed to
a second reader told to refute it. These are the ones that survived; several
were reproduced by running the engine. Line numbers are from the commit that
found them and will drift.

STATUS's "Not built" table turned out to be accurate — nothing listed as a gap
was secretly done. The problem is the other direction, which is the same
failure this file's predecessor recorded: **things listed as built that are
absent or materially thinner than claimed.** A known gap is manageable. A
false claim is not, because nobody goes looking.

Ordered by what a user loses. Struck-through rows are fixed; the rest are
not, and each is a live defect with a plan of its own in
[plans/gaps/](plans/gaps/README.md).

## Files this engine writes that are broken

| What | Where | Consequence |
| --- | --- | --- |
| ~~**Encryption + object streams writes a permanently unreadable file**~~ **FIXED** | `write.rs:675` numbers `/Encrypt` as `max+3`; `write_xref_stream` sizes the table at `max+3` and iterates `0..size`, so that object gets no entry | Reopening reports `is_encrypted=false`, `authenticate()` returns `NotEncrypted`, zero pages — while the content genuinely is ciphertext. Unrecoverable. No test sets both options |
| ~~**Every encrypted file has a wrong trailer `/Size`**~~ **FIXED** | `write.rs:706` writes `max+1` after `:675` emitted `/Encrypt` at `max+3` | Violates 7.5.5 Table 15. Passes only because this engine's own reader walks subsection headers rather than trusting `/Size` |
| ~~**Incremental updates understate `/Size`**~~ **FIXED** | `write.rs:563` takes it from the *changed* set, clobbering the correct value the caller passes at `edit.rs:1139` | A conforming reader must ignore every object above it — including the edited page's own `/Contents`. The object-stream path documents and fixes exactly this bug at `write.rs:781` |
| ~~**`compress` is silently ignored when `linearize` is on**~~ **FIXED** | `maybe_compress` has one caller, `write_entry`; the linearized writer uses `linearize::write_indirect`, which never sees `WriteOptions` | Measured 6,680 bytes against 27,424 for the same document |

## Redaction, whose entire purpose is that content is gone

| What | Where | Consequence |
| --- | --- | --- |
| ~~**Redacting any page but the first silently fails**~~ **FIXED**, along with a second bug in the same expression: a nested form resolved its own names against the page's resources rather than its own (8.10.1) | `redact.rs:257` resolves `/Do` names against `page_refs().first()`; the `page` argument is never threaded into `follow` | Reproduced: a two-page file with the secret image on page 1 reported `images: 0` and left it intact. ## Rendering that is wrong rather than missing

| What | Where | Consequence |
| --- | --- | --- |
| **Optional content (OCG/OCMD) does not exist** | No hits anywhere in `crates/`; `BDC`/`EMC` fall into the catch-all; `/OC` on an XObject is never read | A layer marked `/OFF` paints at full strength with an empty warnings list. In plan 08's scope, in neither STATUS list — plan [06](plans/gaps/06-optional-content.md) |
| ~~**Text clip modes fail open**~~ **FIXED** | `render/lib.rs:654` returns early when an outline does not resolve, before the clip accumulates; `end_text` applies no clip | A base-14 page using `7 Tr` inked the entire canvas. This is the default configuration — the engine ships no faces |
| **Shading patterns work on fills only** | `stroke_pattern` is recorded and read nowhere | A gradient-stroked rule draws solid black with no warning. A *tiling* pattern fill correctly warns; the same pattern stroked paints black silently, which falsifies the "reported with a warning" gap row — plan [07](plans/gaps/07-stroked-patterns.md) |
| ~~**`/Decode` is dropped on the DCT and CCITT paths**~~ **FIXED** | Both return before `/Decode` is parsed | A JPEG with `/Decode [1 0]` renders identically to one without |
| ~~**JPEG and CCITT are unreachable behind any other filter**~~ **FIXED** | Both call `stream_raw`, which is undecoded bytes | `[/FlateDecode /DCTDecode]` renders a placeholder; the CCITT half has no error path and renders silently wrong pixels. The correctly staged bytes already exist and are never called |
| **Inline images bypass the filter chain** | Predictors are passed as `None` despite `/DP` being parsed; DCT and CCITT are refused | A Flate-with-predictor inline image decodes to noise, no error — plan [08](plans/gaps/08-inline-image-filters.md) |
| ~~**Oversized pages are cropped, not scaled**~~ **FIXED** | The shrink factor is computed and never returned | A page beyond the pixel ceiling renders its top-left corner with no warning. Fires on real paper: ANSI E at 300 dpi loses three quarters of the sheet |

## Fonts

| What | Where | Consequence |
| --- | --- | --- |
| ~~**CFF uses the character code as the glyph index**~~ **FIXED** | `resources.rs:909` — no charset, no CFF encoding, no `FDSelect`/`FDArray` anywhere | Code 65 fetched GID 65 — at three sites, not the one this row found. Measured before the fix: a subset font, which is what a producer embeds, drew *nothing at all*, and only a font with more glyphs than the code drew the wrong letter. Now: charset, string INDEX, standard strings, built-in encoding, CID-keyed `ROS`/FDArray/FDSelect, and 9.6.6's fallback order with `.notdef` reported at the end of it |
| ~~**OpenType/CFF renders as blank space, no warning**~~ **FIXED** | `sfnt.rs:46` accepts `OTTO`, so it takes the TrueType branch and `glyf::outline` returns an empty outline, which the renderer reads as a legitimate space | Nothing anywhere looks up the `CFF ` table tag |
| ~~**Predefined CMaps are identity stubs**~~ **FIXED** | `cmap.rs:66` — only `Identity-H`/`-V` were real; fourteen registry prefixes got a blanket 2-byte codespace and code-is-CID | ~~`90ms-RKSJ-H` is mis-split *and* mis-mapped, so the widths are wrong too. `is_approximate` has no callers~~ — all 202 CMaps of Adobe's registry are vendored and compiled at build time into 1.19 MB of deflated tables, behind `cmap-predefined` (default on). The finding was right about both halves and understated the prefix list, which was wrong in *both* directions: `RKSJ` matched nothing, since no registry name begins with it, while `83pv-RKSJ-H`, `78-RKSJ-H`, `Hankaku`, `Roman`, `HKscs-B5-H` and the `UniHojo-*` family matched nothing and fell through to a one-byte-per-code split. Two further defects the row could not see: 9.7.6.2's codespace bounds are per *byte* and were compared as one integer interval, which is exactly what separates GB18030's two-byte and four-byte codes; and 9.7.6.3 gives an undefined code its length from its lead byte, where the code consumed one byte and re-read a trail byte as a lead. `is_approximate` now has a production caller and a stored form on `Font`, and a CMap outside the set is named in a typed warning — plan [03](plans/gaps/03-predefined-cmaps.md) closed |
| ~~**Composite fonts compute the CID for widths but not for outlines**~~ **FIXED**; the vertical half of this row is not, and belongs to plan [05](plans/gaps/05-vertical-metrics.md) | `CMap::cid` had one caller, inside `width_of` | ~~Wrong glyphs at correct spacing. `/CIDToGIDMap` is never read~~ — the CID now decides the glyph as well as the advance, `/CIDToGIDMap` is read in both forms with an out-of-range CID drawing `.notdef` *and reporting*, and the finding understated the defect: the glyph lookup did not use the raw code but sent it through `/ToUnicode` to a character and the character through the font's own `cmap`, which 9.7.4.2 never consults for a composite font. `/W2` and `/DW2` are still absent, so vertical CJK still advances by horizontal widths — plan [02](plans/gaps/02-cid-to-gid.md) closed, plan [05](plans/gaps/05-vertical-metrics.md) open |

## Completeness words that do not hold

- **Phase 07 "complete"** — five plan-scope items absent, including bilinear
  and area-averaged image sampling (nearest-neighbour only, and living in the
  wrong crate) — plan [12](plans/gaps/12-image-sampling.md) — and no quadratic
  curve verb — plan [13](plans/gaps/13-quadratic-path-verb.md).
- **Phase 07 cost** — every paint is O(canvas), not O(shape). `Path::bounds`
  exists and is called nowhere outside its own unit test — plan
  [14](plans/gaps/14-bounded-painting.md).
- ~~**Phase 04 "complete"** — `/Trapped` and three other in-scope items
  absent~~ **FIXED** — plan
  [22](plans/gaps/22-pdf-version-and-trapped.md): the version is now the later
  of header and catalog rather than whichever the catalog says, compared as
  numbers; an unreadable header reports the 1.7 baseline with a
  `HeaderMissing` warning instead of nothing; `/Trapped` is read.
- ~~**Metadata** — the empty-string rule is inverted, so a field present and
  empty reads as absent~~ **FIXED** — plan
  [21](plans/gaps/21-metadata-absent-vs-empty.md).
- **`RenderOptions.cancel`** — documented as checked between scanline bands;
  it is not, so a single very large fill runs to completion — plan
  [15](plans/gaps/15-cancellation.md).

## What to do with this

Fix order is by what a user loses, which is the order above. The four writer
bugs and the redaction bug come first: they produce files that are broken or
that leak, and no amount of downstream work compensates.

The rendering and font findings are all the same shape — a capability that
exists, is reachable, and is wrong in a way that looks plausible. That is the
class this project has been fighting since the first audit, and the reason
every fix in it lands with a test that would have caught it.
